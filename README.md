# Jev Voice Chat

Jevによるターンテイクと、GPT音声を組み合わせた日本語音声対話システムです。ブラウザからマイクで話し、返答を音声で聞けます。話す順番の判定、返答生成、音声合成を分けているため、返答生成部分を別の対話システムに差し替えられます。

| 構成 | 起動ファイル | ブラウザで開くURL |
| --- | --- | --- |
| Jev＋GPT音声 | `start_jev.bat` | http://127.0.0.1:8783 |

返答本文をアプリ側で言い換えずにTTSへ渡します。文字起こし・読み・抑揚は各モデルに依存するため、認識や読み上げの誤りはあり得ます。

## 必要な環境

- Windows、Python 3.11以降。依存パッケージはWindows／Python 3.12で確認したバージョンに固定しています。
- ChromeまたはEdge、マイクと音声出力先。
- OpenAI APIとJev APIを利用できるアカウント、およびインターネット接続。

NVIDIA GPUやNPUは必要ありません。サーバーは同じPCのlocalhostから使う構成です。

## 初回セットアップ

このリポジトリのルートで作業します。以下のコマンド例はPowerShell用です。

1. Windowsの環境変数設定などで、次のキーを設定します。設定後は新しいターミナルを開きます。

   | 環境変数 | 用途 |
   | --- | --- |
   | `OPENAI_API_KEY` | 音声認識・返答生成・GPT音声 |
   | `JEV_API_KEY`または`TYPESAFE_API_KEY` | Jevの判定。いずれか一方を設定 |

   キーはサーバープロセスの環境から読みます。`.env`ファイルの自動読み込みはありません。キーを`config.json`、プロンプト、ソースコード、起動ファイルに書き込まないでください。

2. Python環境を作ります。

   ```powershell
   .\setup.bat
   ```

   `.venv`を作り、`requirements.lock.txt`に固定した依存パッケージを入れます。

3. サーバーを起動します。

   ```powershell
   .\start_jev.bat
   ```

4. 表のURLをブラウザで開きます。「音声をテスト」で出力先を確認し、「音声対話を始める」を押してマイクを許可します。確認音の再生はAPIを使いません。

マイクを使う対話は一度に1つにしてください。終了は画面の「対話を終了する」、サーバー停止は起動したターミナルで`Ctrl+C`です。

## フィラーを使う

返答を準備し始めたとき、同じ声の短いフィラーを1回再生できます。候補は「ええと」「えーと」「えっと」「うーん」「んーと」「あの」の6種類で、直前と同じ候補を避けて選びます。再生中も本文の生成・合成を進め、本文とフィラーは重ねません。

**生成済み音声はリポジトリに含めていません。** 初回は使う声のフィラーを準備してください。

```powershell
.\prepare_fillers.bat --backend gpt
```

`--backend gpt`は省略できます。新規生成は短文6件のAPI呼び出しとなり、少額のAPI料金が発生します。設定が同じキャッシュは再利用します。

準備後はサーバーを再起動し、ブラウザを`Ctrl+F5`で更新します。開始前に「返答前に短いフィラーを入れる」でON/OFFを選べます。対話中は選択を固定し、終了後に切り替えられます。音声が未準備・破損・読み込み失敗の場合は、フィラーを無効にして会話を続けます。

「待って」や短い否定による割込みではフィラーと準備中の返答を止めて続きを待ちます。相槌や追加・訂正は従来どおりJevで判断します。音声認識に時間がかかると、短いフィラーが停止前に終わることはあります。フィラーは本文の字幕や返答履歴に混ぜません。

声・モデル・合成設定を変更した場合は、その設定のフィラーを再生成します。詳しくは[フィラーの準備手順](assets/fillers/README.txt)を参照してください。

## 会話と声の設定

会話の指示は`prompts/chat_ja.txt`、返答生成モデルは`config.json`で変更します。公開版は元の動作設定を引き継いでいます。

| 設定 | 同梱値・役割 |
| --- | --- |
| `model` | `gpt-6.1-sol`。返答生成モデル |
| `reasoning_effort` | `low` |
| `service_tier` | `ultrafast` |
| `greeting` | 開始時の挨拶 |
| `max_output_tokens` | `2000`。推論と返答の生成量上限 |
| `timeout_seconds` | `20`。再試行を含む総待ち時間 |
| `attempt_timeout_seconds` | `8`。初回試行の待ち時間 |
| `max_retries` | `1`。一時的な通信失敗の再試行回数 |

**モデル名・推論設定・サービス階層が、すべてのAPIアカウントで利用できるとは限りません。** 利用するアカウントで対応する組み合わせに変更してください。設定変更後はサーバーを再起動し、新しい会話を開始します。

GPT音声の既定は`gpt-4o-mini-tts`／`marin`です。音声モデル・声を変更する場合は、`speech_client.py`の`MODEL`／`VOICE`を変更し、フィラーも同じ設定で再生成します。詳しくは[フィラーの準備手順](assets/fillers/README.txt)を参照してください。会話設定のファイルを分ける場合は、起動コマンドに`--config config.local.json`などを追加できます。

## 費用・会話記録

音声認識・返答生成・Jevの判定・音声合成はクラウドAPIを利用し、利用料金が発生します。一時的な通信失敗の再試行は追加料金が発生する場合があります。処理を中断しても、すでに行われたAPI利用の課金取消は保証しません。

会話本文・配信結果・診断ログは`data_jev/`に保存します。マイク音声はOpenAIの音声認識へ、文字起こしと必要な文脈はJevと返答生成サービスへ送ります。読み上げ本文もOpenAIへ送ります。

APIキーの値をブラウザへ送る構成にはしていません。会話記録、`.runtime/`、`.venv/`、`models/`、生成フィラー、`.env`などはGitの対象外です。保存場所を変更した場合は、その場所も公開対象から除外してください。

## テストと公開前の確認

Pythonの回帰テストは、リポジトリルートから実行します。

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

Node.js 20以降の標準機能だけで実行できるブラウザ音声・状態処理のテスト:

```powershell
node --test tests/test_browser_audio.cjs tests/test_restart_ui.cjs
```

Playwrightを使う画面テストを含めて実行する場合:

```powershell
npm install
npx playwright install chromium
npm run test:browser
```

これらの自動テストは実APIでの会話や人間による試聴の代わりにはなりません。

GitHubへ追加する前に、公開対象を確認してください。ZIPから展開した場合など、まだGitリポジトリになっていない場合は先に`git init`を実行します。

```powershell
python tools/check_publication.py
git add -n .
```

チェックは作業ファイルとステージ済みの内容の両方を調べ、検出した値そのものは表示しません。秘密情報の完全な検出を保証するものではありません。APIキーや会話記録が候補に含まれないことを確認し、除外対象を`git add -f`で追加しないでください。Gitの対象に入れた後で`.gitignore`を追加しても、過去のコミットにある情報は消えません。
